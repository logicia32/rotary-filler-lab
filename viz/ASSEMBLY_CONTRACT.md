# 組み立てモジュールの契約（作業用）

機械の組み立てをサブシステムごとのモジュールに割った。**1モジュール = 1ファイル = 1担当。**
`viz/scene.py` はモジュールを読み込んで合成するだけにする。

寸法の根拠は `params.json` と `MODEL.md`、部品の API は `viz/parts.py` を見ること。
この資料には**共有する座標と、モジュールが守る形**だけを書く。

---

## モジュールの形

各 `viz/asm_*.py` は次を公開する。これ以外は好きに書いてよい。

```python
"""<サブシステム名>。"""

# このモジュールだけが使う「絵にするためだけの比率」。
# params.json の値に対する倍率で書く。絶対寸法を直書きしない。
PROPORTION = { ... }

# scene.MATERIAL に足す材質。名前は必ずモジュール接頭辞をつけて衝突を防ぐ。
#   例: "drv_cast" / "trf_guide" / "cnv_belt" / "det_estop_red"
MATERIALS = { "drv_cast": dict(color="#4a4f55", pbr=True, metallic=0.35, roughness=0.75), ... }

# scene.DRAW_ORDER に差し込む断片。(メッシュ群の名前, 当てる材質) の並び。
# 群の名前も材質と同じ接頭辞をつける。
#
# 断片は DRAW_ORDER_ANCHOR（("frame","frame") の直後）へ差し込まれる。つまり
# 透過物（暗がり・液・ガラス・ボトル）より先に描かれる。原則は不透明だが、
# コンベアや星車のポケットにボトルを載せるなど透過が要る場合は入れてよい。
# その場合は**末尾へ回した絵と画素単位で一致すること**を確かめて報告に書くこと
# （この環境は深度ピーリングが使えず、描く順だけで前後を合わせているため）。
DRAW_ORDER = (("drv_cast", "drv_cast"), ...)

# このモジュールが回るかどうか。False なら build_static 側、True なら build_carousel 側で組まれる。
ROTATING = False

# 自転する群。群名 -> 自転の中心 (x, y)。テーブル軸まわりではなく、自分の軸で回るもの。
# 中心が違うものは必ず別の群に分けること（1つの群に1つの中心）。
SPIN_CENTERS = {"trf_star_in": (215.67, -215.67), "trf_star_out": (0.0, -305.0)}

def spin_angles(params: dict, lay: dict, state) -> dict:
    """群名 -> 自転角 [rad] を返す。state は scene.MachineState。

    state.cam_angle_rad（カム入力軸角 psi。1タクトで 0->2pi）から出すこと。
    テーブル角からは出せない。テーブルが止まっているあいだに自転するので、
    テーブル角だけでは停留中のどこにいるかが分からない。
    """

def layout(params: dict, lay: dict) -> dict:
    """このサブシステムの絶対座標・寸法を返す。キーはモジュール接頭辞つき。

    引数の `lay` は scene.derive_layout() が返す既存の辞書（読むだけ。書き換えない）。
    返した辞書は scene 側で lay にマージされるので、build() からは lay 経由で読める。
    """

def build(params: dict, lay: dict) -> dict:
    """メッシュ群の名前 -> PolyData（parts.merge 済み）を返す。

    `lay` には layout() の返り値がマージ済みで渡ってくる。
    寸法の数値をここに直書きしない。lay と PROPORTION だけを読む。
    """
```

`build()` が返す辞書のキーは、必ず `DRAW_ORDER` に載っている群の名前であること。
**載っていない群を返すと、その部品は絵に出ない。**

### 担当の境界をまたぐ問題は、自分で直さず報告する

他モジュールのファイルに手を出さない。相手の部品と当たったら、**当たった座標と
どちらを動かすべきかの見立て**を報告に書く。発注側が割り振り直す。
`parts.py` の不足（穴が無い、定数が公開されていない等）も同じ扱いで、基盤担当へ回す。

`SPIN_CENTERS` と `spin_angles()` は自転する部品があるモジュールだけが公開する。
無ければ書かなくてよい。`build()` は**自転角 0 の姿勢で**組むこと（テーブルと同じ規約。
あとから変換行列を当てる）。

## 共有する座標（これは確定値。各モジュールで計算し直さない）

テーブル中心が原点、z が上、単位 mm。世界角は x 軸から反時計回り。
`lay = scene.derive_layout(params)` から取れる既存のキーを使うこと。

| 量 | 値 | 出どころ |
|---|---|---|
| テーブルピッチ円半径 | 225 | `lay["pitch_r"]` |
| テーブル板 外半径 | 280 | `lay["plate_r"]` |
| テーブル板 上面 | 892 | `lay["table_top"]` |
| 架台天板 上面 | 869 | `lay["deck_top"]` |
| ボトル 外半径 / 全高 | 34.0 / 195 | `lay["bottle_r"]` / `lay["bottle_h"]` |
| 充填 / 供給 / 排出 の世界角 | 0° / 315° / **225°** | `params["stations"]` |

### スターホイール（2台）

受け渡しが成立する条件は「ボトル中心がテーブルのピッチ円上とスターホイールの
ピッチ円上に同時に乗ること」。すなわち2つのピッチ円が受け渡し点で接する。

**ポケットのピッチをテーブルのステーション間隔（176.7 mm）に合わせる。** これが要。

| 量 | 値 |
|---|---|
| ピッチ円半径 | **112.5**（PCD 225）= 176.7 / (2π/4) |
| ポケット数 | **4** |
| ポケット半径 | **40**（ボトル半径 34 + 逃げ 6） |
| 外径 | **φ235**（外半径 117.5） |
| 口の幅 | **79.9**（ボトル外径 68 に対し +11.9） |
| 板厚 | 15 |
| **中心の半径** | **337.5**（= 225 + 112.5） |
| 中心の世界角 | 供給 315° / **排出 225°** |
| **速比** | **ちょうど 2.0**（テーブル 45° に対し星車 90° = 1ポケット） |

絶対座標:

```
供給 315deg -> 中心 ( 238.65, -238.65)   受渡点は局所 135deg  コンベア接点は局所 315deg
排出 225deg -> 中心 (-238.65, -238.65)   受渡点は局所  45deg  コンベア接点は局所 225deg

**供給と排出は 2 ステーション（90°）離す。** 1 ステーション（45°）だと 2 台の星車が
抱えるボトルどうしが当たる（中心間 258.3、ピッチ円の隙間 33.3 に対しボトル外径 68）。
逃げ 10 mm を見ると 53.3° 以上が要り、ステーション間隔 45° では 2 つが最小。
2 ステーションなら中心間 477.3、隙間 252.3 で余裕 184。
**実機で供給と排出が離れているのは、この理由。**

### 架台の脚を 22.5° 回す

脚は元々 世界角 45/135/225/315°、半径 340.5 に立っていた。供給星車の中心（半径 337.5・
世界角 315°）と**ほぼ同心**（距離 3.0 mm）で、星車の軸が脚を貫通する。
脚を 22.5° 回して **22.5/112.5/202.5/292.5°** にすると 132.3 mm 空く。

ただし歯車（ピッチ円 φ225・歯先 φ233）は脚まわりに空く 98.3 mm に収まらない。
**歯車は天板の上（z 869.6〜882.0）へ置く。** 脚は天板の下 856.8 で終わるので、
その平面には脚が存在しない。星車の軸も天板を貫かず z 868 で止められる。

**架台に載る部品は、脚の振りに追従させること。** `lay["frame_leg_phase_deg"]`（= −22.5）
を局所角に足して世界角を出す。世界角を直書きすると、脚を回したときに取り残される
（実際に駆動系がまるごと取り残され、腰板を梁が貫通した）。使えるキー:

```
lay["frame_leg_phase_deg"]  -22.5   脚の振り
lay["frame_leg_deg"]         22.5   1本目の世界角（スカラ）
lay["frame_leg_deg_all"]            4本ぶんの世界角
lay["frame_leg_xy"]                 4本ぶんの (x, y)
lay["frame_leg_r"]          340.54
```

### 相手のキーが欠けたときに黙って通さないこと

`lay.get(key, 控え)` は書きやすいが、**相手がキー名を変えたり消したりしても静かに動く。**
実際に `trf_bearing_foot_d` が消えて `0.0` が返り、コンベアの枠が接点まで伸びて
歯車に食い込んだ。**相手のモジュールのキーを読むときは、欠けていたら stderr に
警告を出すこと。**
```

### なぜこの寸法か（**変えるときは必ずここを読む**）

当初は 6ポケット・ピッチ半径 80・中心 305 とし、「テーブルと交互に動かせば
送り量の食い違い（テーブル 176.7 mm 対 星車 83.8 mm）は問題にならない」としていた。
**これは成立しない。** 割出し中に星車が止まっていると、受け渡し点のボトルは
テーブルのピッチ円に沿って動くぶん、星車から見て速く振れる。

```
テーブル  5deg -> ボトルはポケット芯から 19.6 mm 離れる（逃げは 3 mm）
テーブル 10deg -> 39.2 mm
板材との重なり 最大 57/240 点、テーブル角 1〜22deg のあいだずっと
```

位相をどう選んでも消えない。**回避策を作るのではなく、原因を消す。**
ポケットのピッチをテーブルに合わせれば送り量の食い違いが存在しなくなり、
両者を**同時に**動かせる。上の寸法で板材との重なりは **0/360 点**。

速比が 2.0 ちょうどなので、テーブル軸から 2:1 のタイミングベルトで取れる。
カムも位相合わせも要らない。**星車の駆動はテーブル出力から取ること。**

### 高さを必ず分けること（干渉する）

中心距離 337.5 に対し、スターホイール外半径 117.5 とポケット板外半径 235 の和は 352.5。
**平面図で 15 mm 食い込む。**

ポケットのピッチは揃えてあるが（どちらも 176.7 mm）、**円盤どうしは噛み合わない。**
ポケットが同じ位置に来るのは受け渡し点だけで、他の歯は互いを避けない。

**したがって、高さを分ける。** 実機もそうなっている。

| 部品 | z 範囲（テーブル上面 892 基準） |
|---|---|
| ポケット板 | 892 〜 902（t10。ボトルの下部を受ける） |
| スターホイール板 | 962 〜 977（テーブル上面 +70。ボトル胴の中ほどを掴む） |

ボトル全高 195 なので、胴の中ほど（+70〜+85）にスターホイールが来る。
下のポケットにボトルが残り、上のポケットが抜けることで受け渡しが起きる。

### 口の幅（切り欠きの開口）は必ずボトル径を上回ること

外周円とポケット円の交点から出る。

```
x = (R^2 - p^2 + c^2) / (2c)        口の幅 = 2 * sqrt(R^2 - x^2)
     R = 外半径   p = ポケット半径   c = ポケット中心半径
```

ボトル外径 68 に対し 4 mm 前後の逃げを見る。

| 部品 | R | c | p | 口の幅 | 逃げ |
|---|---|---|---|---|---|
| ポケット板 | **235** | 225 | 37 | 72.59 | +4.59 |
| スターホイール | **117.5** | 112.5 | 40 | 79.94 | +11.94 |

`parts.py` の既定値（ポケット板 R245 で口 64.82、スターホイール R100.35 で口 68.18）は
どちらも不足しているので、**上の値を明示的に渡すこと。既定値を使わない。**

### スターホイールは両方とも CW。テーブルと**同時に**動く

テーブルは CCW（供給315° → 充填0° が +45°）。受け渡し点で速度を合わせると、
**スターホイールは両方とも CW**。1割出しで **−90°**（4ポケット）。

**テーブルと同時に動く。** 割出しの 1.5 秒でテーブルが +45°、星車が −90°。
停留の 1.5 秒はどちらも止まる。ピッチが揃っているので受け渡し点での相対速度は 0。

以前「交互に動く」としていたのは、ピッチの食い違いを避けるための回避策だった。
ピッチを合わせた今は不要で、しかも交互では成立しない（上の理由）。

### コンベア

**滑車と同じで、スターホイールは入口と出口でボトルの進む向きが反転する。**
供給側の式をそのまま排出側へ使うと逆向きになる。下は運動学から出した確定値。

| 供給/排出 | 接点 | そこでのボトルの進む向き | コンベアを伸ばす向き |
|---|---|---|---|
| 供給 315° | **(318.20, -318.20)** | (-0.707, -0.707) 機械へ向かう | **(+0.707, +0.707)** |
| 排出 225° | **(-318.20, -318.20)** | **(-0.707, +0.707)** 機外へ出る | **(-0.707, +0.707)** |

**排出は −x。** 以前この表に (+1.000, 0.000) と書いてあったのは誤りで、
ベルトの無い側へボトルを押し出す形だった。症状は3つ出ていた。排出側の三日月ガイドが
排出レーンを塞ぐ／サイドガイドが接点から 300 mm 立たない／ボトルが星車を出た瞬間に
壁に当たる。**すべてこの1つの誤りから出ていた。**

搬送面の高さはテーブル上面 892 と揃える（`lay["table_top"]`）。

排出を −x にすると機械の幅が約 1938 mm に広がり、世界角 225° の操作盤と当たる。
操作盤は空いている角へ移すこと。

### テーブル外周のボトル押さえガイド

半径 262 付近（= 225 + 34 + 3）に、高さ 40〜80 の円弧板。
**供給 315° と排出 225° の位置を切り欠くこと。** 切り欠きが無いとボトルが出入りできない。
`parts.crescent_guide()` は角度範囲で作れるので、2〜3 本の円弧に分けて置く。
2 ステーション離れているので、切り欠きは**2 つに分かれる**（あいだに 270° を含む帯が残る）。

## 全員が守ること

- 自分のファイル以外を書き換えない。`params.json` と他の `.md` も読むだけ。
- git コマンドを実行しない。
- **実在メーカー名・型式を書かない。** 一般名詞だけ。
- 既存の日本語コメントの語り口に合わせる（断定調。です・ます調にしない）。
- 寸法の絶対値をコードに直書きしない。`lay` と `PROPORTION` を経由する。
- **部品が床にめり込まない・空中に浮かない・他の部品を突き抜けない。** 絵を焼いて目で見て確かめる。
