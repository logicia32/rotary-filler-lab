# viz — ロータリー充填機の 3D 描画

機械を組み立てて絵にする。物理はここには無い。動かすときは物理コアのダンプを読んで、
その値をそのまま形にする。

**役割を分けてある。3D は機械の姿と流れ、液面の傾きは 2D の断面パネル
（`bottle_xs`）が担う。** 3D で液面の高さは読めるが、傾きは実際の振幅では読めない。
ピーク 68.074 mrad（3.9deg）を 3D に描いても、傾き 0 との差は **108 万画素中 7808 画素**
しかない。**3D 側で傾きを誇張はしない**（実振幅の絵でなくなる）。記事で傾きを見せる
コマは断面パネルを並べる。

```
python viz/scene.py                          # figs/scene.png（1 枚）
python viz/scene.py --cover                  # 安全カバー付き
python viz/scene.py --camera top             # 視点を変える（表は cameras.py）
python viz/scene.py --cam-angle 270          # カム入力軸角で姿勢を指定
python viz/scene.py --tilt-deg 10 --out figs/tilt_10.png

python viz/animate.py --source cam --camera iso,sensors   # frames/ に連番
python viz/make_gif.py                                     # figs/anim_filler.gif
```

準備:

```
python3 -m venv .venv
pip install -r viz/requirements.txt
```

`requirements.txt` には 2D パネル用の matplotlib も入っている（`viz/panels.py` が
使う）。上の最初の例（`--camera iso,sensors`）はパネルを焼くので、入れずに叩くと
そこで止まる。

| `asm_conveyor.py` | 供給・排出コンベア |
| `asm_details.py` | 操作盤、非常停止、脚、ダクト、トレイ、銘板、配管 |

機械の組み立ては**サブシステムごとに `asm_*.py` へ割ってある**。各モジュールが
守る形（公開する変数と関数）は `viz/ASSEMBLY_CONTRACT.md` が正典。`scene.py` は
それを読み込んで合成するだけで、書かれていないモジュールがあっても標準エラーに
1 行出して飛ばす。

## 何をどう組んだか

形はすべて「断面の折れ線を z 軸まわりに一回転させた回転体」か直方体、または
押し出した多角形から作る。`parts.revolve()` と `parts.extrude_polygon()` が土台。

機械はこう積んである（数値は `params.json` から算出。`scene.derive_layout()` が
唯一の表で、`asm_*.py` の `layout()` が返した寸法もそこへ合流する）。

```
床 ─ アジャスタ脚 ─ 角パイプの架台（4本脚＋上下の桁）─ 丸い天板
   │            脚は世界角 22.5/112.5/202.5/292.5deg（`lay["frame_leg_deg"]`）。
   │            対角に立てるとスターホイールの軸と同心になって貫通する
   ├ 天板の下: カム式インデックスユニット ─ カップリング ─ 誘導ギヤモータ
   │            天板には出力軸の下穴（`lay["deck_bore_d"]`）
   ├ 天板の上: 旋回軸受リング ─ 割出しテーブル（円板＋外周の縁＋中心ハブ）
   │            └ ポケット板（U 溝 8 個。テーブルと一緒に回る）
   │            └ ボトル 6 本（供給から排出までの区間だけ埋まる。残り 2 つは
   │               空ホルダ）＋ 中の液 ＋ 液面の縁 ＋ 接地の暗がり
   │            └ 中心柱（回転軸の頭。短い出っ張りだけ）
   ├ 受け渡し: スターホイール 2 台（供給 315deg / 排出 225deg）＋ 三日月ガイド
   │            ＋ テーブル外周のボトル押さえ（受け渡し部を切り欠く）
   ├ 搬送:     供給コンベア ─ 排出コンベア（どちらも搬送面はテーブル上面と同じ高さ）
   ├ 充填:     天板に立てた支柱＋水平アーム ─ **ノズル 1 本（固定）** ＋ 配管・弁
   ├ 小物:     操作盤・非常停止・シグナルタワー・配線ダクト・液受け・銘板
   └ （任意）安全カバー（受け渡し部は開けてある）
```

組み立ては 4 つに分けてある。**動くものと動かないものを分けておかないと、
コマ送りで同じ部品を何百回も作り直すことになる**。

| 関数 | 何を作るか | コマ送りでの扱い |
|---|---|---|
| `build_static()` | 床・架台・軸受リング・中心柱・ノズルとその支持・カバー＋`ROTATING=False` の `asm_*` | 1 回だけ |
| `build_carousel()` | テーブル板・ハブ・ポケット板・ボトル・稜線・接地の暗がり | 1 回だけ作って、あとは回す |
| `build_liquid()` | 液と液面の縁 | 毎コマ作り直す |
| `build_stream()` | 充填中の液柱（ノズルの下） | 毎コマ作り直す。回らない |

静止画の `build()` はこの 4 つを **`merge_groups()` で**合成する。

> **合成に `dict.update()` を使わない。** `build_static()` も `build_carousel()` も
> どちらも `"steel"` 群を返すので、`update()` でまとめると静止側の金属
> （旋回軸受リング・中心柱・固定ノズル・その支柱とアーム）が丸ごと消える。
> 実際、`asm_*.py` の確認用スニペットがこれをやっていて、945 点あるはずの
> 群が 899 点になり、確認画像にノズルが写っていなかった。
> 群を混ぜるときは必ず `scene.merge_groups(*dicts)` を通すこと。

### 割出しとスターホイールの自転（`cam_angle_rad`）

テーブルは**カム式インデックスユニット**で回る。入力軸は 20 rpm の連続回転で、
1 タクト（3.0 s）で 1 回転する。割付 180 度でテーブルが 45 度進み、残り 180 度は
停留。この入力軸の角を **psi** と呼び、`MachineState.cam_angle_rad` に入れる。

```
psi   0 〜 180 deg : 割出し。テーブル CCW +45deg と同時に、スターホイールが CW -90deg
psi 180 〜 360 deg : 停留。テーブルもスターホイールも止まる
```

**テーブルとスターホイールは同時に回る。** 交互に動かす設計は途中でやめた。
星車のピッチをテーブルに合わせた（4 ポケット・ピッチ半径 112.5・速比ちょうど 2.0）
ので、割出し中は歯車で噛んだまま 2 倍の角速度で回り、テーブルの 45deg に対して
星車は 90deg。**受け渡しはこの噛み合ったまま起きる。** 交互に動かしていた頃は、
割出し中にボトルが星車の板を突き抜けた（重なり 最大 57/240 点）。位相をどう選んでも
消えず、そこでピッチを揃える形に変えた経緯がある。

**テーブル角からは停留中のどこにいるかが分からない**（止まっているので値が
動かない）。停留のどこにいるかを描くには psi が要る。だから姿勢の出どころを
psi に一本化してある。

| 関数 | 何を返すか |
|---|---|
| `scene.cam_angle_from_time(params, t)` | 時刻 [s] -> psi [rad]（積み上がる） |
| `scene.table_angle_from_cam(params, psi)` | psi -> テーブル角 [rad] |
| `scene.table_alpha_from_cam(params, psi)` | psi -> テーブルの角加速度 [rad/s2] |
| `scene.cam_phase(params, psi)` | psi -> (割出しの進み具合 0..1, 何回目か) |

変形正弦の式そのものは `panels.modified_sine()` が持っていて、`scene` はそれを
呼ぶだけ（`panels` は線図を描くために matplotlib を読むので、呼ぶときに読み込む）。
`animate.cam_table_motion()` も同じ道を通る。**式は 1 箇所だけ。**

スターホイールは**テーブル軸ではなく自分の軸で回る**ので、テーブルと同じ回転では
動かせない。モジュール側が次の 2 つを公開すると、`scene` と `animate` の両方が
「中心へ寄せて z 軸まわりに回して戻す」変換を当てる。

```python
# viz/asm_transfer.py（中心は供給 315deg / 排出 225deg、半径 337.5 の位置）
SPIN_CENTERS = {"trf_star_in": (238.65, -238.65), "trf_star_out": (-238.65, -238.65)}

def spin_angles(params, lay, state) -> dict:
    """群名 -> 自転角 [rad]。state.cam_angle_rad から出す。"""
```

- 中心が違うものは必ず別の群に分ける（1 つの群に 1 つの中心）。
- `build()` は**自転角 0 の姿勢で**組む。姿勢は後から変換行列で当てる。
- 静止画は `scene.build()` が焼き込み、コマ送りは `animate.FrameRenderer` が
  アクタの `user_matrix` に入れる。**どちらも `scene.spin_matrices()` を読む。**
- 目で確かめるときは `--cam-angle` を振る。**0 -> 90 -> 180 でテーブルと
  スターホイールが一緒に動き（テーブル 0/22.5/45deg に対し星車 0/-45/-90deg）、
  180 -> 270 -> 360 では両方止まったまま、が正しい。** 停留のあいだ天板の上は
  1 画素も動かない（`top` の 180deg と 270deg で変化画素 0.000%）。
  実機と同じで、そこが分かる絵になっているかを見る。
- **停留中に動いて見えるものは天板の下にある。** 入力軸はタクトのあいだ 20 rpm で
  回りっぱなしなので、かさ歯車 -> 縦軸 -> 半月ドグ -> 近接センサ の並びだけは
  停留中も psi で回る。天板の下を覗く画角にすると、そこで機械が「止まっていない」
  ことが読める（`asm_drive.py` の home カメラ）。

  ```
  azimuth   = drv_angle_deg + 55
  elevation = -6
  注視点     = 局所 (drv_takeoff_x, 0) を世界へ回した点・z 約 780
  view_span_x_extent_d = 約 0.16
  ```

### ノズルは 1 本で、テーブルと一緒には回らない

物理側は「世界座標に固定された 1 本のノズルがあり、停止中にその下へ来た
ステーション 1 本だけを充填する」という作りになっている。絵もそれに合わせてある。

- ノズルの世界角は `params.json` の `stations.fill_deg`（0 度）で、
  `lay["fill_deg"]` から読む。**テーブル角を変えても動かない。**
  コマ送りでも `build_static()` の側に入れてあるので、原理的に回らない。
- `station_under_nozzle(n, table_angle_rad, nozzle_deg)` に世界角を渡す。
  以前はモジュール変数を `derive_layout()` が書き換えていて、呼ぶ順で答えが
  変わった。控えの角度は `scene.DEFAULT_STATION_DEG` の 1 箇所だけ。
- 支柱はテーブル外周より外の天板上に立て、そこからアームを内側へ張り出して
  ノズルをくわえる。テーブルとは縁が切れている。
- 充填中の液柱は、そのノズルの真下のステーションにだけ描く。ステーションが
  `scene.STREAM_ALIGN_TOL_DEG` より大きくずれていたら（＝割出しの途中なら）描かない。
- ノズル 8 本を一斉に注ぐ絵にすると処理能力が 8 倍になり、`params.json` の
  タクトと合わなくなる。合わせるべきは物理側。

### そのほか

- **液の色は水。** `params.json` の `liquid.name` は water なので、`MATERIAL["liquid"]`
  も淡い青の半透明にしてある。無色に振り切るとガラスと見分けが付かないので、
  水色をわずかに残して液面の高さを読ませる。縁（`rim`）は液面の線で、液より濃く
  しないと真横から見たとき面が消える。
- **安全カバーは受け渡し部を開けてある。** 全周の円筒にするとスターホイール
  （中心半径 337.5・外半径 117.5）を串刺しにし、コンベアの出入り口も塞ぐ。開ける
  角度は `scene.cover_arcs()` が、スターホイールの張り出し `asin(R/c)` に余裕を
  足して決める。板は `parts.cover(..., arcs=...)` が円弧ぶんだけ張る。
  既定では**描かない**（`--cover` で付く）。
- **カバーは半径を内法にして、外へ積む。** `lay["cover_r"]`（341.6）は板の
  内面で、板厚 4.1・枠・支柱はそこから外へ出る（枠の外面 371.7）。以前は
  半径を板の外面にして枠と支柱を内側にも張り出させていたので、テーブル外周の
  液受け溝の立ち上がり（外壁 334.8〜338、z 868〜894）に下枠と支柱が 9 mm
  食い込んでいた。溝は内へ寄せられない（内側は外周ガイドの据付座で止まり、
  溝の帯が 15 mm を切る）ので、カバーの側を外へ出してある。
  **これに合わせて架台天板を φ694 から φ756 に広げた。** 支柱と枠（371.7）と
  脚の外角（374.6）が天板（半径 378）の上に載る。
  端の支柱は円弧の端に芯を置かず、外側の面を板の端に合わせて内側へ寄せてある。
  芯を端に置くと支柱の半分が開口へはみ出し、受け渡しの門型の脚（半径 361.6 の
  251.9 / 288.1deg に太さ 12.8）と同じ所を通る。
- **中心柱は短い出っ張りにしてある。** 回転軸の頭が見えれば足りる。ボトルの
  高さまで伸ばすと、斜め上から見たとき奥のボトルを 1 本隠す。
- ボトルは外形だけの中実。中空にすると半透明表示で内部の面が濁る。
  ガラスは液面が透ける程度に薄く、そのままだと形が読めないので、肩・首・口元の
  稜線だけ細い輪でなぞって光を乗せている（`parts.bottle_edges()`）。
- 接地感は、ポケット板の上に薄い暗がりの円環を 3 枚（内から外へ薄く）貼って出す
  （`parts.flat_ring()`）。影が使えないので、面を直接暗く汚す代わりの手。
  **暗がりはテーブル板の縁で頭を抑える。** 板より外へ出すと、下に何も無いところに
  暗がりだけが浮いてボトルが宙に立って見える。

液は円柱を傾いた平面で切って作る（`parts.liquid()`）。液面の縁だけ別に細い管でなぞって
（`parts.liquid_rim()`）、傾いた楕円が目で追えるようにしてある。液面の高さは

```
z(theta) = 液深 + R * tan(tilt) * cos(theta - 傾きの向き)
```

で、切る位置を液面の中心に置いているので、傾けても液量はほぼ変わらない。

## 視点

構図の表は **`cameras.py` が唯一**（以前 `scene.CAMERA` にあった 1 個は
`cameras.CAMERAS["iso"]` へ移した。画角の決め方はその後、機械の外接円柱を
枠に当てはめるやり方に変えてある）。

| 名前 | kind | 何を見せるか |
|---|---|---|
| `iso` | 3d | 斜め上。機械全体の姿 |
| `top` | 3d | 真上。8 ステーションの割出しと工程配置（供給 315 / 充填 0 / 排出 225） |
| `nozzle` | 3d | 充填ステーションの寄り。液面が上がっていくところ |
| `bottle_xs` | 2d | ボトル 1 本の断面（`panels.py`） |
| `cam` | 2d | カム線図。入力軸角とテーブル角の関係 |
| `sensors` | 2d | 波形パネル。3D と時刻を合わせて走る |

名前と説明の正典は `params.json` の `viz.cameras` で、`cameras.check_names()` が
食い違いを並べる。

**画角は機械の実測外形から出す。** テーブル径の倍率で決めていたときは、外へ
部品を足すたびに枠から外れた（テーブル φ560 に対し、いまの機械は幅 2065 ×
奥行 1435、水平の最大半径 1079、高さ 0〜1217、カバーを付けると 1245）。
組み上がったメッシュから `scene.extent_from_meshes()` が測り、
`scene.ensure_extent()` が `lay` に入れる。`cameras.machine_radius()` /
`machine_top()` / `machine_bottom()` がそれを読む。測っていなければ
テーブル径の控えに落ちるので、`resolve()` を自分で呼ぶときは先に
`scene.ensure_extent(lay, meshes, params)` を通すこと。

- **`iso` は外接円柱を枠に当てはめて決める**（`view_fit_x_extent`）。機械を
  実測の最大半径と上下端の円柱で押さえ、その上下の縁を実際に投影して、
  縦にも横にもはみ出さない最小の距離まで `cameras._fit_extent()` が詰める。
  注視点の高さも同時に決まり、機械の上下の中央に来る。
  画面の縦だけで決めていたときは、横 2065 × 高さ 1245 の横長の機械に対して
  上が大きく空き、注視点がボトルの高さ（z 989）にあったせいで下は逆に
  切れていた（実測で画面の下端を 12% はみ出していた）。いまは実際の機械が
  縦 89% 横 71% を占める。残りは外接円柱と機械の形の差。
  横縦比が要るので、`apply()` は Plotter の窓から測って渡す（既定は 4:3）。
- `top` は外接円の直径の 1.00 倍を画面の縦に入れる（平行投影。画面の縦が
  そのまま実寸）。真上から見ると外接円がそのまま枠に接するので、当てはめでも
  同じ値になる。
- `nozzle` だけは寄りの絵なので、ボトル全高の倍率のまま。機械が育っても寄りは変えない。
- 「画面の縦に入れる高さ」を `resolve()` に渡すと（`view_span_x_extent_d` など）
  そちらが勝って古い決め方に戻る。駆動系・受け渡し系の寄りの確認画像はこの
  形で撮っているので、`iso` の当てはめを変えてもそれらは動かない。
- 高さの基準も実測。`lay["total_height"]` は安全カバーの上端（1221.6）で、
  カバーの上枠（1245.4）はそれより高い。

ターンテーブルは `cameras.turntable(lay, n)` が方位角だけ 360 度回した並びを返す。
`iso` の当てはめは外接円柱なので方位角に依らない。ぐるり回しても枠の大きさが
動かず、機械が伸び縮みして見えることがない。

## 描く順

**`scene.DRAW_ORDER` が唯一の表。**（`animate.DRAW_ORDER` はもう無い。以前は
同じ並びを 2 箇所に写していて、部品を足すと片方だけ古くなった。）
`(メッシュ群の名前, 当てる材質)` の並びで、`asm_*.py` の断片は読み込み時に
`("frame", "frame")` の直後へ差し込まれる。**群の名前がここに無い部品は絵に出ない。**

テーブルと一緒に回る群も同じで、**`scene.rotating_groups()` が唯一の表**。
コマ送りはこれを読んでアクタの変換行列を差し替える。

## 状態を渡して描く

1 コマぶんの状態は `MachineState` にまとめてある。1 枚だけ欲しいときは `render_state()`。

```python
import sys; sys.path.insert(0, "viz")
import scene

params = scene.load_params()
lay = scene.derive_layout(params)

st = scene.MachineState(
    table_angle_rad=0.42,          # テーブル角
    volumes_mL=[400, 140, ...],    # ステーションごとの液量
    tilt_t=[0.05, 0.02, ...],      # 接線方向の傾き [rad]
    tilt_r=[0.00, 0.01, ...],      # 半径方向の傾き [rad]
    filling_index=1,               # 液柱を描くステーション。None で描かない
    cam_angle_rad=1.57,            # カム入力軸角 psi。自転する部品の姿勢
)
scene.render_state(params, lay, st, "frames/0001.png", size=(1600, 1200))
```

- 液量から液深への変換は `volume_to_level()`（`h = V / (pi R^2)`、胴高さで頭打ち）。
- 傾きは接線・半径の 2 方向で受け取り、`tilt_to_world()` が
  「傾きの大きさ」と「液面が上がる向き」に直す。正のとき、その向きの側で液面が上がる。
- `filling_index` に渡すのは「いま充填しているステーション」。ノズルの真下から
  外れているコマでは液柱を描かないので、割出し中のコマにそのまま渡してよい。
- `cam_angle_rad` は既定 0。渡さなければ自転する部品は割出しの始まりの姿勢で止まる。
- **同じ状態を渡せば必ず同じ絵になる。** 乱数もコマ間の持ち越しも無く、
  別の状態を挟んでから同じ状態に戻しても PNG がバイト単位で一致する。
  静止画（`render_state()`）を 2 回、コマ送り（`FrameRenderer`）で別の状態を
  挟んでから戻す、のどちらも一致を確かめてある。連番でちらつかない。
- ただし**静止画とコマ送りのあいだ**は、自転する部品まわりの数百画素だけ
  1〜9 階調ずれる。静止画は自転を頂点に焼き込み、コマ送りはアクタの変換行列で
  当てるので、法線の丸めが違う。同じ道の中では一致するのでちらつきには効かない。

## 動かす

```
python viz/animate.py --dump core/out.bin --start 0.5 --duration 1.5 --jobs 3
python viz/animate.py --source cam --camera iso,top,nozzle,sensors
python viz/animate.py --turntable 36 --turntable-mode hold
python viz/make_gif.py --step 3 --width 640
```

視点は 1 つに限らない。`--camera` に名前を並べると、**1 コマぶんのメッシュを
組んだあと、カメラだけ当て替えて続けて焼く**。2D パネルを混ぜてもよく、どちらも
同じ時刻列で出るので `viz/compose.py` に渡せばそのまま合成アニメになる。
視点が 2 つ以上のときは `frames/<視点名>/f0000.png` のように分ける（`--subdirs`）。

2D パネルの画素数は `--panel-size` で変えられるが、**下限がある**。パネルの字は
matplotlib の点数で決まっていて px 数に付いてこないので、小さくすると字だけが
相対的に大きくなり、軸の名前がタイトルに重なる／タイトルが右端で切れる。
下限を割った指定は下限まで広げて、標準エラーに 1 行出す（波形パネルは
段数 x 120 px も足す）。

**`--source` の既定は `dump` で、読むのは `core/out.bin`。** 手元に無ければ作る
（`core/` で `make && make run`。1 タクトぶんが `core/out.bin` に出る）。無いまま
素で叩いたときは、次の一手を添えて止まる。

```
$ python viz/animate.py
core/out.bin が無い。物理コアの出力を読む道（--source dump）はここから始まる。
  先に物理コアを回してダンプを作る（core/ で make && make run）か、
  絵の作りだけ確かめるなら --source cam を付ける
```

区間がダンプの外のときも同じで、落ちずに区間を添えて止まる。

```
$ python viz/animate.py --start 7.2 --duration 1.0
core/out.bin: 区間 7.200 〜 8.200 s がダンプの外。ダンプにあるのは 0.000 〜 2.000 s
```

以前置いてあったダンプはタクト 2.4 s の版（サーボ駆動）の記録で、`params.json` の
カム式・3.0 s とは別の機械のものだった。**焼き直す前に、ダンプがいまの諸元で
取ったものかを確かめること**（`read_dump` が版と諸元を要約して出す）。

物理コアの書き直しが済むまでは `--source cam` を使う。カム曲線から作った
仮の値で、絵の作りと時刻合わせだけを確かめられる（**値そのものに物理的な
意味は無い。絵にもそう書いてある**）。液面の揺れの周波数は `params.json` に
無いので `animate.SLOSH_FREQ_HZ` に 1 つだけ置いてある。容器の内半径と液深から
出る値で、機械の諸元ではないから諸元表には載せない。

### 絵にしている値

`--source dump` ならすべてダンプから来る（`core/FORMAT.md` の並び）。
見栄えのために数字は作らない。

| 絵 | ダンプの項目 |
|---|---|
| テーブルの回転角 | `th_t` |
| ボトルの液量（液深） | `V_i`（m^3。mL は 1e6 倍） |
| 液面の傾き（接線・半径） | `phi_t_i` / `phi_r_i` |
| 充填中のステーション | `V_i` が増えているステーション |
| カム入力軸角 psi | ダンプに無いので時刻から出す（入力軸は一定回転） |

- 傾きは `MODEL.md` 2 節の `tilt_t = phi_t`, `tilt_r = phi_r` をそのまま使う。
  正のとき、その向き（接線は回転の進む向き、半径は外向き）の側で液面が上がる。
- 充填中かどうかは、時刻をこちらで組み立てずに液量の増減から読む。
- ログは 4000 Hz、コマは `params.json` の `sim.frame_rate_hz`（**30**）。
  補間はせず、各コマの時刻にいちばん近いレコードをそのまま使う（約 133 本に 1 本）。
- 読み込みは `sensors/read_dump.py` をそのまま使う。版の判定も警告もそちらに任せる。

### 速さ

**ここがこのラボでいちばん重い所。** すべて 960x720、ソフトウェア OpenGL での実測。
この機械は別の計算とコアを分け合うことがあり、**絶対値は混み具合で 2〜3 倍動く**。
同じ時間帯に取った対どうしで比べること。

| 何を | 実測 |
|---|---|
| iso 単独 41 コマ（SSAA、3 並列、`asm_*` 4 本あり） | **1.51 s/コマ**（61.9 s） |
| 本番 60 コマ x（3D 3 視点 ＋ 波形パネル）= 240 枚 | **235.3 s / 32.9 MB** |
| 480x360・`--aa none`・3 視点・4 並列 | 3.98 s/コマ（1.33 s/枚） |
| `build_static()`（`asm_*` 4 本を足す前 -> 後） | 0.27 -> 2.45 s |
| `FrameRenderer.__init__`（同上） | 1.5 -> 4.7 s |
| 毎コマの液の組み直し（同上） | 0.13 -> 0.15 s |

> 上の 2 行は取り直した値。前は 1.20 s/コマ・175.7 s と書いてあったが、
> 部品が増えたあとの同一条件（960x720 / SSAA / 3 並列 / 41 コマ）で計り直すと
> 25〜34% 遅い。**見積もりに使うならこちらを使う。**

- **効く順**: ①描画器を使い回す ②回らない部品を作り直さない ③1 コマぶんの
  メッシュを組んだら視点だけ変えて続けて焼く ④解像度を下げる ⑤並列に回す。
  `Plotter` を作るたびに環境マップの前計算とシェーダの構築が走るので、
  ①だけで 3 倍以上取れる。描画器の下ごしらえは `scene.new_plotter()` が唯一。
- 部品が増えて重くなったのは**組み立ての初回だけ**で、毎コマの手間はほぼ変わって
  いない。回らない部品は 1 回しか組まないので、この作りが効いている。
- 並列数はコア数まで。ソフトウェア OpenGL 自身も複数スレッドを使うので、
  4 コアで 4 プロセス以上に増やしても取り合いになるだけ。
- アンチエイリアス（SSAA）は内部で 2 倍の解像度に描くので、これだけで 2.8 倍かかる。
  急ぐときは `--aa none`。既定は付けたまま。
- 進み具合（何枚中何枚・s/コマ・残り時間）は標準エラーに出る。

### GIF にする

この環境に **ffmpeg は入っていない。imageio も入っていない**。PIL だけで書く。

```
python viz/make_gif.py --step 3 --width 640 --colors 192
python viz/make_gif.py --frames frames/iso frames/top --out-dir figs --step 1
```

- `--src-fps` の既定は `params.json` の `sim.frame_rate_hz`（30）。**ここが連番を
  焼いたコマ数と食い違うと、GIF だけが早回しになる**（既定が 60 のままだったとき、
  30 コマ/s で焼いた連番がそのまま 2 倍速になっていた）。
- **既定のコマ間隔は 100 ms**（`--step 3` x 連番 30 コマ/s = 10 コマ/s）。50 ms ではない。
  30 コマ/s の連番からは `--step` だけでは 50 ms に届かない（30/step は
  30 / 15 / 10 / 7.5 / 6 / 5 …）。**50 ms（20 コマ/s）が要るなら連番を 20 コマ/s で焼く**
  （`viz/animate.py --fps 20` -> `make_gif.py --src-fps 20 --step 1`）。
  30 コマ/s の連番を `--src-fps 20 --step 1` で読ませても 50 ms にはなるが、
  そちらは 1.5 倍の早回しになるので、時刻を書いた絵には使わない。
- **GIF のコマ間隔は 10 ms 刻みしか持てない。** PIL は指定 [ms] を 10 で割って切り捨てる
  ので、割り切れないコマ数を選ぶと再生が速くなる（30 コマ/s = 33.3 ms は 30 ms になり
  11% 早回し）。20 コマ/s か 10 コマ/s なら丁度。
- 全コマ共通のパレットを 1 つ作って使い回す。コマごとにパレットを作ると、
  動いていない画素まで色番号が変わって差分が効かなくなる。
- 色数を 256 未満にしておくと、PIL が「前のコマと同じ画素」を透過色で塗ってくれる
  （`optimize=True`）。背景と架台が 1 画素も動かないので、ここがよく効く。
- `--width` は**縮めるだけ**。元より大きい値を渡しても拡大せず、標準エラーに 1 行出す。
- **差し色はパレットの枠を先に取ってやらないと全部落ちる。** メディアンカットは
  画素数だけで色を選ぶので、面積の小さい彩度の高い色に 1 枠も回らない。
  3D 3 視点と波形を貼り合わせた 12 コマ（幅 640・192 色）で計ると、
  **波形の赤い時刻カーソルが 1092 px -> 0 px**、シグナルタワーの橙黄 768 px -> 0 px、
  液の水色は 2 割まで痩せた。**`--colors 255` にしても 0 px のまま**（同じ 12 コマで確認）。
  枠を取る側（いまの既定）では **カーソル 1092 px -> 1316 px（120%）**、
  橙黄 109%、水色 58%、容量は 0.23 MB で変わらない。
  枠に入れる色は `scene.MATERIAL` と `panels.COLOR` の色相を目印にして、
  **絵に出てきた実際の画素から選ぶ**（材質の色そのものは光が当たると現れない。
  シグナルタワーの赤 #b5241d に対し、絵の中の赤い画素の平均は #a85b56 だった）。
  比べたいときは `--no-accents` で切れる。
- **PNG では合っているので、PNG を見て通すと GIF の色落ちに気付けない。**
  記事に貼るのは GIF のほうなので、確かめるときは GIF を開く。
- **実測（60 コマ・幅 640・192 色）**: iso 0.28 MB / top 0.22 MB / nozzle 1.41 MB /
  3D と波形の合成 0.37 MB。記事に貼る上限として 5 MB を見ている。超えると
  標準エラーで言う。

### mp4 が要るとき

**この環境では動かない**（ffmpeg が無い）。入っている所へ `frames/` を持っていって、

```
ffmpeg -framerate 30 -i frames/f%04d.png -c:v libx264 -crf 20 \
       -pix_fmt yuv420p -movflags +faststart figs/anim_filler.mp4
```

横幅が奇数だと libx264 が通らないので、そのときは
`-vf "scale=trunc(iw/2)*2:trunc(ih/2)*2"` を足す。

## 寸法を変えたいとき

1. **機械の寸法**は `params.json` を直す。ここには数値を持たない。
   ピッチ円・ステーション数・テーブル外径・板厚・ボトル寸法・充填量・タクトは
   全部そこから来る。
2. **絵にするためだけの比率**（架台の脚の太さ、カバーの半径、ノズルの長さなど、
   解析に効かない値）は `scene.py` の `PROPORTION`、モジュールの分は各
   `asm_*.py` の `PROPORTION`。すべて `params.json` の値に対する倍率で書いてある
   ので、寸法が変わっても機械の格好は崩れない。
3. **色と質感**は `scene.py` の `MATERIAL`（モジュールの分は各 `MATERIALS`）、
   背景は `BACKGROUND`。名前が衝突したら読み込み時に止まる。
4. **構図**は `cameras.py` の `CAMERAS`。方位角・仰角・画角に加えて、
   「画面の縦に入れる大きさ」を倍率で指定していて、そこから距離を逆算する。
5. 各部の絶対座標は `scene.derive_layout()` が返す辞書に集約してある。
   「どこに何があるか」を調べたいときはこれを読む。
6. 部品を足したら **`DRAW_ORDER` に 1 行足す**。足し忘れるとその部品は絵に出ない。

## この環境で踏んだ落とし穴

- **画面が無くてもそのまま描ける。** `Plotter(off_screen=True)` が VTK のソフトウェア
  OpenGL で通るので、xvfb は要らない。`start_xvfb()` も呼んでいない。
- **深度ピーリングは使えない。** 有効にすると半透明の面がまるごと落ちる。
  描く順（不透明 → 接地の暗がり → 液面の縁 → 液 → 液柱 → ガラスの稜線 → ボトル → カバー）で
  前後を合わせている。順序は `scene.DRAW_ORDER` にある。
  **コマ送りでアクタを消して足し直すとこの順が崩れる**ので、
  中身のメッシュだけ差し替える（`animate.FrameRenderer._swap()`）。
  `add_mesh` は法線を作る算法を挟んでからマッパへつなぐので、その入口を差し替えれば
  陰影の作り直しまで付いてくる。
- **影も既定で切ってある。** `enable_shadows()` を立てると手前の半透明が欠ける。
  `--shadows` で立てられるが、不透明だけの絵を作るとき用。
- **真上視（`top`）は白飛びする。** ポケット板が真上を向いた大きな平板なので、
  金属の正反射と環境マップの天面が重なって飛ぶ。ステーション位置は読めるが
  板のディテールは消える。
- 回転掃引は回転軸上（r=0）で潰れた三角形を作る。放置すると円板の中心から
  放射状の白い筋が出るので `parts._drop_degenerate()` で捨てている。
- **平らな面どうしを同じ高さに置かない。** 円板は中心から切った三角形の集まりなので、
  ボトルの底とテーブル面をぴったり同じ高さにすると奥行きの取り合いになり、
  半透明のボトル越しに放射状の縞が出る。ボトルは板厚のわずかな量だけ沈めて、
  底の面をテーブルの陰に隠してある（`PROPORTION["bottle_sink_x_plate_t"]`）。
- 金属を PBR で描くと映り込む先が無いと真っ黒になるので、無地の環境マップを
  コードで作って渡している（`scene.studio_cubemap()`）。外部の画像は使わない。
  既定の前計算は重すぎるので、サンプル数を落としてある。
- 視点を手で置いたあとは `reset_camera_clipping_range()` を呼ぶ。呼ばないと
  手前の部品が切れることがある。
- **回る剛体はメッシュを作り直さず、アクタの変換行列（`user_matrix`）を差し替える。**
  液の傾きは接線・半径の局所量なので、テーブル角 0 で組んでから z 軸まわりに
  回した結果は、最初から回した角度で組んだものと一致する。だから液も同じ扱いでよい。
  自分の軸で回る部品も同じで、当てる行列が違うだけ（`scene.spin_matrix()`）。

## 確認用に出してある絵

`figs/` に置いてある。**GIF は `anim_` で始める、というのはこちらの約束で、
コードは強制していない**（`make_gif.py` にフォルダを複数渡したときだけ
`anim_<フォルダ名>.gif` になる）。上書きしたくない図があるなら名前を確かめること。

| file | 中身 |
|---|---|
| `figs/anim_filler.gif` | 割出し 2 サイクルぶん。テーブルが回り、停止中に 1 本だけ注がれる |
| `figs/anim_filler_cover.gif` | 同じ区間に安全カバーを付けたもの |
| `figs/scene.png` / `scene_cover.png` | 既定の 1 枚とカバー付き |
| `figs/tilt_00.png` / `tilt_05.png` / `tilt_10.png` | 全ステーションを 0/5/10 度に揃えたもの |
| `figs/table_mid.png` | テーブルを 22.5 度（割出しの途中）まで回したところ |

> **ここにある絵は全部、スターホイール・コンベア・駆動・小物を足す前の機械。**
> テーブルとボトルとノズルしか写っていない。記事に使う前に焼き直すこと。
> 焼き直すと 5 枚とも差し替わる。

静止画で 5 度の傾きが読みにくいのは承知のうえ。液面の縁を太くして無理に見せると
不自然になるので、**傾きは 2D の断面パネル（`bottle_xs`）に任せる**。実振幅
（ピーク 3.9deg）では 3D の絵で差が 108 万画素中 7808 画素にしかならない。
3D で見せるのは機械の姿と、液が入っていく流れのほう。
