# sensors — 仮想センサ層

物理コアが吐く「理想の物理量」から、**センサが実際に返すであろう数字**を作る。

理想の加速度をそのまま並べたものはセンサ信号ではない。取り付け位置の伝達、帯域制限、
サンプリング、ノイズ、量子化、レンジ飽和を通して初めて、検出アルゴリズムの試験になる。
ここが甘いと「検出できました」が机上の話になる。

取り決めは `SENSORS.md`、バイナリの並びは `core/FORMAT.md`、式の裏づけは `py/NOTES.md`。
`params.json` は読むだけで書き換えない（足したい定数は `PARAMS_ADDED.md`）。

## 使い方

```
.venv/bin/python -m sensors.demo                  # 図を出す（figs/sensor_*.png）
.venv/bin/python -m pytest -q sensors/test_chain.py
.venv/bin/python sensors/read_dump.py core/out.bin        # ダンプの中身を覗く
.venv/bin/python sensors/read_dump.py <path> loose        # 未対応の版を仮定して読む
```

コードから使うとき:

```python
from sensors.read_dump import load_run
from sensors import virtual

dump, events = load_run("core/out.bin")              # 連続ログ RFILL004 ＋ イベント列 RFEVT002
params, added = virtual.load_params("params.json")   # 足りない定数は既定値で補う
impacts = virtual.bearing_events(events, params)     # イベント列から軸受の衝撃を作る
chans, truth = virtual.synthesize(dump, params, seed=20260722, impacts=impacts)

ch = chans["strain"]
ch.t, ch.y          # センサ出力（時刻とデータ）
ch.truth            # 同じ量の真値（ログ周波数のまま）
ch.info             # 各段が何をしたかの記録（LSB、間引き比、飽和数…）
```

`seed` が同じなら、何度回しても同じ配列が返る。チャネルごとに種を分けてあるので、
軸どうしのノイズは相関しない。

## 信号連鎖（SENSORS.md 2 節）

```
真値（物理コアの状態から合成）
 → 取り付け位置の伝達      2 次系 1 つ。柱／軸受箱の局所モード
 → 交流結合               圧電センサだけ（highpass_hz）。DC 結合のセンサは素通り
 → 帯域制限               2 次バターワース低域通過（bandwidth_hz）
 → サンプリング            ログ周波数からセンサのサンプリングへ
 → ノイズ加算              白色ガウス。種で再現できる
 → 量子化                 LSB = full_scale / 2^bits（full_scale = 2×range の両振り）
 → レンジ飽和              ±range で頭打ち
```

各段の考え方:

- **フィルタは因果（片方向）で回す。** 実機のフィルタは位相を戻せないので、
  `filtfilt` のような零位相化はしない。そのぶん群遅延が出るが、それも含めてセンサの出力。
  係数は双一次変換（プリワープ込み）で、`scipy.signal.butter` と一致することを試験で確認している。
- **サンプリング**は、比が整数なら単純な間引き、整数にならなければ（帯域制限済みの信号を）
  出力側の時刻に線形補間する。センサのほうが速いときは既定で拒否し、
  `allow_upsample=True` を明示したときだけ補間で埋める（情報は増えないことを承知の上で）。
  実際のログ周波数は公称値と一致しないので（下記）、ここは整数比になるとは限らない。
- **ノイズ**は加速度だけ密度指定。`rms = density * sqrt(bandwidth * 1.11)`
  （1.11 は 2 次バターワースの雑音等価帯域）。ひずみと電流は rms 直接指定。
  雑音はサンプリング後に乗せるので、指定 rms が 0〜fs/2 に一様に広がる近似になっている。
- **量子化**の LSB は `full_scale / 2^bits`。両振りのセンサでは `full_scale = 2 * range`
  （±2 g なら 4 g ぶん）。飽和は量子化のあとなので、出力は必ず LSB の整数倍。

## 加速度センサが 2 つある理由（SENSORS.md 5.5）

| | `accel_lf` | `accel_hf` |
|---|---|---|
| 取り付け | 架台の柱（世界角 0） | 軸受箱 |
| 結合 | DC | 交流（2 Hz） |
| サンプリング / 帯域 | 1 kHz / 200 Hz | 51.2 kHz / 10 kHz |
| レンジ / 分解能 | ±2 g / 16 bit | ±50 g / 16 bit |
| 狙い | 揺れ（3.75 Hz）と回転同期成分 | 軸受の衝撃（3 kHz のリンギング） |

1 つで両方は見られない。`figs/sensor_two_accels.png` がその 2 枚:

- 3 kHz のリンギングを 1 kHz サンプリングの `accel_lf` に通すと、帯域制限が無ければ
  **偽の低周波イベント**になる（3000 Hz はちょうど 0 Hz に落ちるので、見かけの大きさは
  標本化の位相しだいで毎回変わる。規定どおり 200 Hz で帯域制限すれば -27 dB まで落ちる）。
- 逆に `accel_hf` は取り付けが硬く（局所共振 1.2 kHz）交流結合なので、3.75 Hz の揺れは
  自分の雑音の床から 70 dB 以上下に沈む。

## 衝撃はイベント列で扱う

連続ログは 4 kHz（実際は 3846 Hz）なので、3 kHz のリンギングはナイキストを割る。
そこで衝撃は波形としてログから読まず、**発生時刻と振幅**として受け取り、
センサ層が各センサの刻みで減衰振動に合成して足す（`impact_train`）。
合成は 51.2 kHz 以上・リンギングの 16 倍以上の内部刻みで行い、
そこから各センサの帯域制限と間引きを通す。だから低速センサでは正しく落ち、
高速センサでは正しく残る。

**現行（rev.3）の物理コアはイベント列を別ファイル（`<out>.events` / RFEVT002）に出す。**
`load_run()` が連続ログとイベント列をまとめて読み、`bearing_events(events, params)` が
その中の軸受衝撃（kind=0）を取り出す。旧版はコアがイベント列を出さず、`bearing_events()`
がテーブル角の発生規則から時刻を再生成していたが、いまはコアの出力をそのまま使う。

カムフォロワ当たり（旧バックラッシュ相当）は `cam_events()` がイベント列から拾う。
どちらも加速度への注入はしていない。トルクから架台の加速度への腕の長さが決まらないため。

## 読む側の注意

- **実際のログ周波数は公称値と違う。** コアは `round(1/(log_rate_hz*dt))` ステップごとに
  書くので、`log_rate_hz = 4000` の指定に対して実際は 3846 Hz（4 % 違う）。
  `Dump.log_rate_hz` は時刻列から測った実際の値を返す。公称値は
  `Dump.header.nominal_log_rate_hz`。ここを取り違えるとスペクトルの周波数軸が全部ずれる。
- 版が上がるとヘッダ長もレコード長も変わる。`read_dump` は magic で分岐し、
  想定と違えば黙って読まずに落ちる。どうしても読みたいときだけ
  `strict=False` / `allow_unknown_version=True`（後者は `h == V/(pi R^2)` などの
  不変量で検算してから読む）。
- 版 002 は反力 `F_tab_t` / `F_tab_r` をコアが出しているので、そのまま使う。
  版 001 のログにはそれが無いので、ステーションごとの状態から組み直す。
  一致は `verify_reaction()` で確かめる。これは参照とセンサ方位ぶんを**成分ごと**に
  引いた残差なので、全体符号の反転（~2.06）や接線・半径の取り違え（~1.4）が残る。
  版 002 は参照と同じ座標・同じ式なので残差は 5e-6 まで落ちる。版 004 は world 座標の
  `f_tab_*` を分解し、参照側は `np.gradient` で速度を作るので ~0.055 に増える
  （符号・軸は正しく、この 5.5% は数値微分と既知省略ぶん）。

## この諸元で分かったこと

- 3.75 Hz の揺れが自分の雑音の床より上に出るのは **ひずみゲージだけ**（+6 dB ほど）。
  加速度センサは、架台を接地した構造とみなすかぎり 60 dB 以上下に沈む。
  ここは取り付けのモデル（`structure_model`）でかなり動くので、
  `demo.py` が 3 通りの置き方で数字を出す。誇張しないためにその表を必ず見ること。
- ひずみのスロッシング成分は、量子化ノイズの床に対して **90 dB 以上** 上にある。
  24 bit / 500 ustrain だと LSB が 6e-5 ustrain で、量子化はまったく効かない。
  効いているのはアンプの雑音（0.5 ustrain rms）のほう。
- `accel_lf` は逆に、信号（〜1e-6 m/s^2）が 1 LSB（6e-4 m/s^2）よりずっと小さい。
  ノイズを 0 にすると出力は全部 0 になる。実センサでは自分の雑音がディザとして働く。

## まだやっていないこと

- 検出側（次数比分析・包絡線解析）。信号を作るところまでが今回の範囲。
- 充填量アンバランスとバックラッシュの、加速度への注入。
- `accel_hf` の連続量は、4 kHz のログを 51.2 kHz へ補間して作っている。
  ログのナイキスト（1.9 kHz）より上に本来あるはずの成分は入っていない。
  そこを見たいなら、コアのログ周波数を上げるか、イベント列で受け取る必要がある。
