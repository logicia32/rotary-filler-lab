# analysis — 検出層

仮想センサが出した信号から、異常を拾えるかどうかを試す層。このラボの到達点。

物理は `MODEL.md`、センサは `SENSORS.md`、バイナリの並びは `core/FORMAT.md`、
式の裏づけは `py/NOTES.md`。ここは読むだけで、`core/` `py/` `sensors/` `viz/`
`params.json` には手を入れない。

結果は `analysis/RESULTS.md`、図は `figs/analysis_*.png`。

## 何をする層か

物理コアを条件ごとに回し、センサ層で信号を作り、次の 4 つの特徴量に落として、
正常データから作った基準としきい値で判定する。

| 特徴量 | 何を見るか | 狙う故障 |
|---|---|---|
| 次数比分析 | 回転角で等間隔に並べ直してから FFT。次数 1 = 回転同期 | 充填アンバランス |
| スロッシング帯 | 時間軸のスペクトルで 3.75 Hz 付近の実効値とピーク | 液の揺れ（回転に同期しない） |
| 包絡線解析 | 帯域通過、絶対値、低域通過の順に通し、角度領域で FFT | 軸受外輪傷 |
| 衝撃検出 | 包絡線のしきい値越えでイベント時刻を拾う | 軸受・バックラッシュ |

## 使い方

```
# 総当たり（コアの実行から図まで）。ダンプは大きいのでリポジトリの外に置く
.venv/bin/python -m analysis.run_matrix \
    --workdir /path/to/work --filler /path/to/filler-copy

# 図だけ描き直す（workdir に figdata.npz と results.json が残っていれば）
.venv/bin/python -m analysis.figures --workdir /path/to/work

# 特徴量の検証（外部データに依存しない）
.venv/bin/python -m pytest -q analysis/test_features.py
```

`--filler` に渡すのは物理コアの実行ファイル。`core/` は別の担当が改修することが
あるので、解析を回す前にコピーを退避して、そのコピーを指すこと。使ったコピーの md5 は
`results.json` と `RESULTS.md` に控える。

1 条件 480 s のダンプが 623 MB になる。`--workdir` は作業領域を指し、
リポジトリの中を指さないこと（`.gitignore` は `*.bin` を無視するが、そもそも置かない）。

## ファイル

| ファイル | 役割 |
|---|---|
| `config.py` | 解析側の取り決め（窓の長さ・帯域・何 σ か）。理由を全部添えてある |
| `features.py` | 回転角リサンプル・次数比・包絡線・帯域パワー・衝撃検出 |
| `detect.py` | 正常データから基準を作ってしきい値判定。誤警報率の見積もり |
| `dataset.py` | 物理コアの実行、ダンプの読み込み、センサ信号の合成、窓の切り出し |
| `run_matrix.py` | 総当たりの本体。表を標準出力へ、数値を results.json へ |
| `figures.py` | 図。`figs/analysis_*.png` にしか書かない |
| `test_features.py` | 特徴量の検証。合成信号だけで完結する |
| `RESULTS.md` | 結果と、そこから言えること・言えないこと |
| `PARAMS_ADDED.md` | params.json に足すなら、という提案（本体は触っていない） |

## 押さえておくところ

- 停止区間の扱い。テーブルは割出しと停止を繰り返すので、停止のあいだ角度が進まない。
  角度領域には停止区間を入れない、という取り決めにした。理由と代償は `features.py` の
  冒頭と `RESULTS.md` 2 節。
- 窓は整数回転。そうしないと次数比の整数次がビン中心に乗らない。
- 基準と試験で乱数の種を変える。同じ種で作った基準に自分を当てても試験にならない。
- 見えなかったものは見えなかったと書く。表の空欄には理由（帯域外・雑音床の下）を入れる。
- ここで出る数字は「この物理とこのセンサ諸元の下では」まで。実機の実測ではないし、
  合わせ込みもしていない。
