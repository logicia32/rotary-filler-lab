# ロータリー充填機の仮想ツイン

8 ステーション間欠ロータリー液体充填機の仮想ツインです。実機を用意せずに、機械の物理から
センサ信号を合成し、異常監視のアルゴリズムを組んで検証するための実験環境です。

これは実機の実測ではありません。図面と一般的な水準の諸元から物理モデルを起こし、その上で
信号を合成したもので、実機に合わせ込んだ数字でもありません。主張できるのは「この物理と
この諸元の下では」というところまでで、諸元を変えれば数値は変わります。

## 構成

| ディレクトリ | 役割 |
|---|---|
| `py/`       | 物理リファレンス（仕様書。C はこれに突き合わせて検証する） |
| `core/`     | C の物理コア。状態をバイナリのダンプに書き出す |
| `sensors/`  | 仮想センサ層。理想の物理量からセンサ出力を作る（伝達・帯域制限・量子化・飽和） |
| `analysis/` | 検出層。故障 × センサ × 特徴量の総当たり |
| `viz/`      | 3D の組み立てと描画。部品はメッシュを使わずコードで生成する |

諸元の正典は `params.json` です。すべての数値の出どころで、コードには数値を直書きしません。
式と符号の取り決めは `MODEL.md`、センサ諸元は `SENSORS.md`、ダンプ形式は `core/FORMAT.md`
にあります。

## 準備

```
python -m venv .venv
pip install -r requirements.txt
```

## 使い方

```
# 物理コアをビルド
cd core && make && cd ..

# テスト（Python リファレンスと C の一致まで）
python -m pytest -q

# センサ信号の図を出す
python -m sensors.demo

# 故障 × センサの総当たり（作業領域はリポジトリの外に置く）
python -m analysis.run_matrix --workdir <作業領域> --filler core/filler
```

図（`figs/`）とアニメーションのコマ（`frames/`）は生成物なので、リポジトリには含めません。
上のコマンドで作り直します。

### シリーズ共通のフック GIF

「名前の付いた失敗（液面スロッシュ）」を *異常 vs 正常* の A/B で、5機共通のビジュアル言語（隅のシリーズバッジ `n/5 · machine · category`・暖色＝失敗／寒色＝正常）で見せる短い GIF です。`figs/hook_zenn.gif`（16:9・記事用）と `figs/hook_li_1x1.gif` / `figs/hook_li_4x5.gif`（1:1・4:5・SNS 用）。パレット最適化のシームレス GIF で各 8 MB 未満（この環境に ffmpeg が無いので mp4 は出しません）。`.venv/bin/python viz/make_hook.py` で再生成します（既存の 3D パイプラインは回さず、`figs/anim_filler.gif` のコマを再利用します）。

## 主な結果

`analysis/RESULTS.md` に、どの故障がどのセンサで見えるかの総当たり結果をまとめています。
この 4 センサ（加速度 2 種・ひずみ・電流）で明快に検出できるのは軸受外輪傷だけ、というのが
この諸元での結論です。1 つのセンサで全部は見えず、4 つ足しても全部は捕まりません。

## 断り書き

- 実機の実測ではありません。合わせ込みもしていません。諸元を変えれば数値は変わります。
- 摩擦（効率・引きずり・粘性）、モータ出力、電流モデル、素ユニットの許容慣性は仮定した値です。
- センサの取り付け位置と荷重経路は暫定です。加速度センサの構造モデル（接地／自由）は
  結果を大きく左右しますが、実機か構造解析がないと決まりません。
