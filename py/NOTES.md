# 式の裏取りと近似の限界

スロッシングの式を、実装とは独立に確かめた記録。
記事のパラメータ表と「近似の限界」の節はここから書ける。

実物は見ていないので、確かめられるのは「式が文献のとおりか」と
「params.json の値を入れたら何が出るか」だけ。合わせ込みは一切していない。

params.json は rev.3（カム式インデックスユニット＋誘導ギヤモータ）。
機構が変わって消えた話（台形プロファイル・カスケード制御のゲイン）は
8 節・9 節に履歴として残してある。

---

## 0. 結論だけ先に

params.json rev.3 の値（内半径 R = 32.5 mm、液深 h = 120.5 mm、水、g = 9.80665 m/s²）で:

| 量 | 値 |
|---|---|
| 固有角周波数 w1 | 23.5705 rad/s |
| **固有振動数 f1** | **3.75136 Hz** |
| 周期 T1 | 0.26657 s（= 1/3.751360。0.26661 は誤り） |
| 等価振り子長 L1 | 17.652 mm |
| 等価質量比 m1/m_liq | 0.1225（液 400 g のうち 49 g） |
| 割出し 1 回のピーク傾き | 68.07 mrad（dz/R = 0.068） |
| 停留に入ってからの残留 | 35.30 mrad（コリオリ込み） |

- `eps1 = 1.8412` は J1'(x)=0 の第 1 根で正しい。厳密値 1.8411837813406595 との差は相対 8.8e-6。
- `w1^2 = (g*eps1/R)*tanh(eps1*h/R)` は文献の式と一致した（出典は 2 節）。
- `L1 = g/w1^2` も文献の等価振り子長と厳密に一致する（3 節）。
- 等価質量比 `m1/m_liq` は文献の式と一致した（3 節）。ref.py が `slosh_mass_ratio()` として持つ。
- 液面の傾き ≒ 振り子角の近似が効くのは、壁での波高が R の 0.1 倍まで（傾き 5.7° 相当）。
  0.2 倍（11.3°）を超えると波が砕けたり回ったりして線形理論の外（4 節）。
- **rev.3 の割出しはこの限界の中に収まる**（4.4 節）。接線加速度のピークが 0.0443 g で、
  傾きのピークは 68.07 mrad = dz/R 0.068。限界 0.2 の 1/3。
  前版（台形・割出し 0.40 s）は 0.68 g で、参照実装が 95° まで振り切れていた。
  機構が変わって、モデルが責任を持てる範囲に入った。
- **コリオリを入れると 1 次モードが w1 ± Omega の 2 本に割れる**（10 節）。
  この機械では分裂幅が共振の半値幅より広いので、入れるかどうかで残留揺れが 8% 変わる。

## 1. eps1 = 1.8412 は J1'(x)=0 の第 1 根か

確かめた。二通りで一致する。

- `scipy.special.jnp_zeros(1, 5)` → `[1.84118378, 5.33144277, 8.53631637, 11.7060049, 14.86358863]`
- `scipy.optimize.brentq` で `scipy.special.jvp(1, x, 1)` の根を直接解いて 1.841183781340659。
  そこでの J1' は 5.6e-17。
- テスト側（test_ref.py）は scipy を使わず、J0/J1 を級数で組んで
  `J1'(x) = J0(x) - J1(x)/x` の根を二分法で出している。同じ値になる。

MODEL.md の 1.8412 と厳密根の差は相対 8.8e-6。
w1 は eps1 の平方根で効くので、固有振動数への影響は相対 4.4e-6 = 3.75 Hz に対して
0.000016 Hz。丸めたままで問題ない。

高次モードの根も出しておく（4 節で使う）: eps2 = 5.3314、eps3 = 8.5363。

## 2. 固有角周波数の式の出典

**取れた。一次資料に当たった。**

### 出典 A（主）

Franklin T. Dodge, *The New "Dynamic Behavior of Liquids in Moving Containers"*,
Southwest Research Institute, San Antonio, Texas, 2000.
https://www2.swri.org/www2/fluid-slosh/dodge-sp-106-update.pdf
（同じものが https://www.vibrationdata.com/tutorials/SwRI_SLOSH_Update.pdf にもある）

これは NASA SP-106 の著者側（SwRI）自身による改訂版。序文に、SP-106 は 1966 年に
Abramson の主導で編まれたが絶版になったため、この改訂版を用意した、と書いてある。

第 1 章 1.4 節「Circular Cylindrical Tank」、式 (1.40):

```
omega_mn^2 = (g*lambda_mn / a) * tanh(lambda_mn * h / a)
```

ここで `a` はタンク半径、`h` は液深、`lambda_mn` は `dJ1(lambda*r/a)/dr = 0`（r = a）の根。
続く式 (1.41) で、m = 1（反対称モード）の根を `xi_n` と書き、

```
xi_1 = 1.841   xi_2 = 5.331   xi_3 = 8.536 ...   xi_(n+1) -> xi_n + pi
```

としている。**MODEL.md の式と記号を置き換えただけで完全に同じ。**

同じ節に、m = 1 のモードだけがタンクに正味の力とトルクを与えるので、
横方向・ピッチ方向の運動で励起される主要モードだ、という説明がある。
ロータリテーブルの割出し（水平加速度）で効くのが 1 次反対称モードだという
MODEL.md の前提は、ここで裏が取れている。

なお Dodge 版の表 3.2 は、この円筒タンクの結果を Bauer に帰している:
H. F. Bauer, *Fluid Oscillations in the Containers of a Space Vehicle and Their
Influence on Stability*, NASA TR R-187, 1964.

### 出典 B（表面張力込みの一般形／記号まで一致）

Gianni Cassoni, *Curvature-corrected sloshing spectra for cylindrical tanks in
microgravity*, arXiv:2605.00168（2026-04-30）
https://arxiv.org/abs/2605.00168 / 本文 https://arxiv.org/html/2605.00168

式 (28):

```
omega_mn^2 = ( g + (sigma/rho) * eps_mn^2 / R^2 ) * (eps_mn / R) * tanh(eps_mn * h / R)
```

`eps_mn` は「m 次ベッセル関数の導関数 J'_m の n 番目の正の零点」と定義され、
1 次反対称モードで eps_11 ≈ 1.841。**MODEL.md の `eps1` という記号そのもの。**
sigma = 0 と置くと MODEL.md の式に戻る。

### 原典（現物は確認していない）

H. N. Abramson (ed.), *The Dynamic Behavior of Liquids in Moving Containers,
with Applications to Space Vehicle Technology*, NASA SP-106, 1966.
NTRS: https://ntrs.nasa.gov/citations/19670006555

書誌は確認したが、本文 PDF は開いていない。式の確認は上の出典 A（同じ系列の改訂版）で取った。
記事で SP-106 を引くなら「Dodge による改訂版で確認した」と添えるのが正確。

### 表面張力を無視してよいか（このスケールでの確認）

ボトルは R = 32.5 mm と小さいので、いちおう見た。水（sigma = 0.0728 N/m）で:

- ボンド数 rho*g*R^2/sigma = 142 → 重力支配。
- それでも式 (28) の毛管項を入れると **f1 は 3.751 Hz → 3.796 Hz（+1.18 %）**。

1 % 強なので、MODEL.md が重力項だけにしているのは妥当。
ただし記事で「3.75 Hz」と書くなら、有効数字 3 桁目はこの近似で動く程度、とは言える。

## 3. 等価振り子への置き換えと等価質量比

### 振り子長 L1 = g/w1^2 は妥当か → 妥当。文献の式と厳密に一致する

出典 A の表 3.2「Model Parameters for a Cylindrical Tank」（直径 d = 2R で書かれている）:

```
Pendulum length,  L_n = d / ( 2*xi_n * tanh(2*xi_n*h/d) )
```

d = 2R を入れると `L_n = R / ( xi_n * tanh(xi_n*h/R) )`。
一方 MODEL.md の `L1 = g/w1^2` に `w1^2 = (g*xi/R)*tanh(xi*h/R)` を代入すると同じ式になる。
恒等的に一致するので、これは近似ではなく定義の言い換え。test_ref.py で数値でも確認済み
（`test_pendulum_length_matches_formula`）。

params の値では **L1 = 17.652 mm**。深水側なので `R/eps1 = 17.653 mm` とほぼ同じ。

### 等価質量比

同じ表 3.2:

```
Slosh mass,  m_n = m_liq * [ d * tanh(2*xi_n*h/d) ] / [ xi_n * (xi_n^2 - 1) * h ]
```

d = 2R で整理すると

```
m_n / m_liq = 2R * tanh(xi_n*h/R) / [ xi_n * (xi_n^2 - 1) * h ]
```

n = 1 は `xi_1*(xi_1^2 - 1) = 4.4005` なので `2/4.4005 = 0.4545 = 1/2.2`、つまり

```
m_1 / m_liq = (R / (2.2*h)) * tanh(1.8412*h/R)
```

という、よく引用される形になる。params の値で:

| モード | m_n / m_liq | 質量 |
|---|---|---|
| 1 次 | 0.1231 | 49.0 g |
| 2 次 | 0.00370 | 1.5 g |
| 3 次 | 0.00088 | 0.35 g |
| 剛体扱いの残り m_0 | 0.872 | 347 g |

液深が深い（h/R = 3.71）ので、**揺れるのは液 400 g のうち 49 g（12.25 %）だけ**で、
残りは「凍った液」として容器と一緒に動く。
（上の表は h = 120 mm での値。rev.3 の液深 120.5 mm では 1 次が 0.1225。）

**実装での扱い（rev.3 で入れた）:**

1. `slosh_mass_ratio()` として上の式をそのまま持っている。
2. **二重計上を避ける。** `J_load` に液の全質量を入れると、液は全部凍っている前提になる。
   等価振り子を入れた以上、
   - 剛体分 `m_0 = m_liq*(1 - 0.1225)` が Rp に付き、
   - スロッシング分 `m_1` は振り子として別に動き、その反力 `-Rp*m1*a1_t` が軸に返る。
   `simulate()` はこちら。`load_inertia()` の既定（液を全量剛体）は諸元表の J_load を
   出すためのもので、両方やると 12 % 過大になる。差はピークトルクで -1.0 %。
3. 振り子の支点位置（hinge location）は表 3.2 に式があるが、
   **どこを基準にした高さなのかが本文から特定できなかった**（基準を定義する図が
   PDF のテキストからは読めない）。深水極限では支点が静止液面のあたりに来て、
   質量が L1 = 17.7 mm 下にぶら下がる形になる、という理解までは取れた。
   曲げモーメントの腕の長さを液面基準で取るなら要確認。いまは軸まわりの
   モーメントしか出していないので使っていない。

## 4. 近似の限界

### 4.1 「液面の傾き = 振り子角」はどこまで許されるか

**静的には厳密。動的には 2 割ほど安全側（こぼれを多めに見る）。**

- 静的な極限では、水平加速度 a に対して真の液面は傾き a/g の平面になる。
  一方 MODEL.md の運動方程式の定常解は `phi = -a/g` で、これも a/g。
  つまり `tilt = phi` と `dz = R*tan(tilt)` は静的つり合いでは厳密。
  test_ref.py の `test_step_acceleration_settles_at_a_over_g` がこれを確認している。
- ところが自由振動でリンギングしているときは、揺れているのは 1 次モードの形
  `J1(eps1*r/R)*cos(theta)` であって平面ではない。
  傾き a/g の平面を J1(eps_n r/R) で展開して、壁での持ち上がりへの寄与を数値で出すと:

  | モード | 壁での持ち上がりの寄与 | 累積 |
  |---|---|---|
  | 1 次 | 0.837 | 0.837 |
  | 2 次 | 0.073 | 0.910 |
  | 3 次 | 0.028 | 0.938 |
  | 4 次 | 0.015 | 0.952 |
  | 5 次 | 0.009 | 0.961 |

  1 次モードだけで静的な壁高さの 83.7 % を説明する。残り 16 % は高次モードで、
  これらは固有振動数がずっと高い（f2 = 6.4 Hz、f3 = 8.1 Hz）ので、
  ゆっくりした励振ではほぼ静的に追従する。
- したがって `dz = R*tilt` は、
  - ゆっくりした加速度に対しては（高次モードも静的に効くので）ほぼ正しく、
  - f1 で鳴っているときは 1 次モード分の壁高さを **1/0.837 = 1.19 倍に見積もる**。

  誤差は 2 割弱で、向きは「こぼれを多めに見る」側。設計判断としては安全側。

### 4.2 tan と小角近似

`dz = R*tan(tilt) ≈ R*tilt` の差は、tilt = 0.1 rad で 0.33 %、0.2 rad で 1.3 %。
4.1 のモード誤差（2 割）に比べれば無視できる。ref.py は tan のまま実装してある。

### 4.3 振幅の限界（線形スロッシングが成り立つ範囲）

出典 A の第 2 章に、実験に基づく明確な数字が二つある。

- 円筒タンクの減衰の節: 減衰が振幅に依存しないのは
  「壁での波高が R の 0.1 倍を超えない限り」。
  > "the damping is independent of the wave amplitude – as the correlations assume –
  > so long as the slosh amplitude at the wall is no greater than about 0.1R"
- バッフル設計の節:
  > "a slosh wave starts to become noticeably nonlinear and splashes, rotates, etc.,
  > when the amplitude exceeds about ten percent of the tank diameter.
  > Consequently, the largest feasible slosh amplitude that can be assumed reasonably is 0.2R"

これを傾き角に直すと（dz/R = tan(tilt)）:

| dz/R | 傾き | 意味 |
|---|---|---|
| 0.1 | 5.7° (0.100 rad) | ここまでは減衰も線形とみなせる |
| 0.2 | 11.3° (0.197 rad) | これを超えると砕ける・飛ぶ・回る。線形モデルの外 |

ref.py はこの二つを `TILT_WARN_RATIO` / `TILT_INVALID_RATIO` として持ち、
`linearity_flag()` で ok / warn / invalid を返す。

もう一つ、線形モデルが構造的に表現できないものがある。**スワーリング**
（出典 A 3.6 節）で、接線方向と半径方向の**非線形**結合により、液面の節線が
ぐるぐる回る運動。rev.3 でコリオリ（線形の結合）を入れたので、
「2 方向が独立」という前提そのものは無くなり、共回転／逆回転の円モードは出る。
ただしそれは容器が回っていることによる線形の結合で、大振幅で出るスワーリングとは別物。
非線形結合は入っていないので、記事で「回る揺れ」に触れるならここを区別して書くこと。

### 4.4 カム式の割出しは適用範囲の中に収まる（前版は外れていた）

変形正弦・割出し角 45°・割出し時間 1.5 s（タクト 3.0 s の半分。割付 180° の帰結）で:

- 最大角速度 0.92133 rad/s → 半径方向 `a_r = -Rp*omega^2` = -0.191 m/s² = **-0.0195 g**
- 最大角加速度 1.92962 rad/s² → 接線方向 `a_t = Rp*alpha` = 0.4342 m/s² = **0.0443 g**

接線方向の静的つり合いだけなら傾き **44.27 mrad**。
参照実装（コリオリ込み・満量・静止から 1 タクト）を回すと

| | 傾き | dz/R |
|---|---|---|
| 割出し中のピーク | 68.07 mrad（静的の 1.54 倍） | 0.068 |
| 停留に入ってからの残留 | 35.30 mrad | 0.035 |

限界 0.2 の 1/3、警告しきい値 0.1 の 7 割。

定常運転では前のサイクルの残りが次の割出しに乗るので、これより大きくなる。
3 サイクル回すと最大 **89.6 mrad**（dz/R = 0.090）。それでも 0.2 は割らない。

前版（台形・割出し 0.40 s）は 0.676 g で、静的つり合いだけで 38.7°、参照実装が 95° まで
行っていた。「モデルが成立する側にタクトを合わせる」という順序の逆転もそこで起きていた。
rev.3 は割出し時間がカムの割付（180°/180°）から決まるので、選ぶ余地そのものが無い。

**残留はタクトの取り方で大きく動く。** 割出し時間 T とスロッシング周期 T1 の比で決まり、
T/T1 が整数のあたりで残留が落ちる。1.5 s は T/T1 = 5.63 でほぼ最悪側にある。
これはカムの割付とタクトから決まってしまうので、この機械では選べない。

## 5. 減衰比 zeta = 0.005 の裏取り

params.json は「滑面円筒容器の値として仮置き（感度解析の対象）」としている。
出典 A 第 2 章に、実験相関式が二つ載っているので当てはめた。

無次元数は `Re1 = nu / sqrt(g*R^3)`（レイノルズ数の逆数に相当。特性寸法は半径 R）。
params の値で `Re1 = 5.450e-5`。

- Mikishev & Dorozhkin (1961)、式 (2.6a):
  `zeta = 0.79*sqrt(Re1) * [1 + 0.318/sinh(1.84h/R) * (1 + (1-h/R)/cosh(1.84h/R))]`
  → **zeta = 0.00584**
- Stephens et al. (1962)、式 (2.7a):
  `zeta = 0.83*sqrt(Re1) * tanh(1.84h/R) * [1 + 2(1-h/R)/cosh(3.68h/R)]`
  → **zeta = 0.00613**

液深による変化（Mikishev & Dorozhkin）:

| h | zeta | f1 |
|---|---|---|
| 20 mm | 0.00747 | 3.380 Hz |
| 50 mm | 0.00604 | 3.738 Hz |
| 80 mm | 0.00587 | 3.751 Hz |
| 120 mm | 0.00584 | 3.751 Hz |

**params.json の 0.005 は、相関式の 0.0058〜0.0061 に対して 15〜20 % 低いだけ**で、
桁も傾向も合っている。仮置きとしては十分に妥当。
記事で「仮置き」と書くより「滑面円筒の実験相関で 0.0058、それに対し 0.005 を採った」と
書けるようになったので、ここは強くなった。

ただし断り書きが要る。この相関は清浄な液・滑面の剛体タンクの実験値で、
実際の食品用ボトルの内面・液の性状・首の絞りは入っていない。
また容器が空から満たされていく過程（出典 A に「液を抜いているときは減衰がやや増える」
という記述がある）も入っていない。

## 6. こぼれ判定の保守性

MODEL.md 5 節は「`h + dz` が上限を超えたら、その超過分をこぼれた体積として積算」と
書いている。素直に読むと断面積を掛けて `pi*R^2 * (h + dz - body_height)` になる。
ref.py はそのとおり実装した（`apply_spill`）。

ただしこれはかなり多めに見積もる。実際に縁を越えるのは、傾いた液面が縁の平面を切る
楔状の部分だけで、断面積いっぱいではない。超過 e が小さいときの体積を積分すると

```
V_spill ≈ (8/15) * sqrt(2R) * e^(5/2) / s^(3/2)      s = tan(tilt)
```

（これは私が導いた漸近形。数値積分と、e = 1 mm で数 % の一致を確認した。）

R = 32.5 mm での比較:

| 傾き | 超過 e | 厳密な楔 | MODEL.md の pi*R^2*e | 比 |
|---|---|---|---|---|
| 0.05 rad | 1 mm | 0.358 mL | 3.32 mL | 0.11 |
| 0.10 rad | 1 mm | 0.131 mL | 3.32 mL | 0.039 |
| 0.20 rad | 1 mm | 0.046 mL | 3.32 mL | 0.014 |
| 0.20 rad | 3 mm | 0.697 mL | 9.95 mL | 0.070 |

**1〜2 桁の過大評価になる。** 「こぼれたか否か」の判定（超過が正か）は変わらないが、
「何 mL こぼれたか」を数字として出すなら、上の楔の式に差し替えるか、
少なくとも「こぼれ量は上限値」と断ること。

ref.py は柱のまま（C 実装と突き合わせる基準なので、勝手に変えると突き合わせが
成立しない）。rev.3 の既定条件では液面が縁に届かないので、この差は出てこない。

## 7. params.json の値で出る固有振動数（記事のパラメータ表用）

R = 32.5 mm、水、g = 9.80665 m/s²、eps1 = 1.8412。

| 液深 h | 体積 | f1 | 周期 T1 | L1 |
|---|---|---|---|---|
| 5 mm | 16.6 mL | 1.971 Hz | 0.508 s | 64.0 mm |
| 10 mm | 33.2 mL | 2.686 Hz | 0.372 s | 34.4 mm |
| 20 mm | 66.4 mL | 3.381 Hz | 0.296 s | 21.7 mm |

| **120 mm（fill_height）** | **398.2 mL** | **3.751 Hz** | **0.26657 s** | **17.65 mm** |

### 桁の常識との照合

3.75 Hz、周期 0.27 s。手に持ったマグカップやコップの水が揺れる周期が
だいたい 0.3 秒前後という体感と合う。式の形からも、周期は `sqrt(R/g)` で決まり、
R = 32.5 mm なら `sqrt(0.0325/9.8) = 0.058 s`、これに `2*pi/sqrt(1.8412) = 4.63` を
掛けて 0.267 s。桁は合っている。

### 「h が変わると w1 も変わる」の実際の効き方

MODEL.md 2 節は毎ステップ h から w1 を計算し直せと強く言っている。式としてはそのとおりだが、
**このボトル形状では効くのは充填のごく初期だけ**である点は書いておく価値がある。

`tanh(eps1*h/R)` は h/R が 1.5 を超えるとほぼ 1 に飽和する。R = 32.5 mm なので
h = 50 mm（166 mL）で f1 は最終値の 99.7 %。つまり
**f1 が 2.7 Hz から 3.75 Hz へ動くのは最初の 100 mL 程度の間**で、
流量 330 mL/s ならこれは 0.30 秒。充填 1.21 秒のうちの 1/4 で、それ以降は定数と区別がつかない。

「毎ステップ計算し直せ」という指示自体は正しく、浅い側では確かに大きく効く。
ただし記事で「充填が進むと固有振動数が動くのが肝」と書くなら、
どの区間で効いているのかまで示さないと誇張になる。

解消したあとも項目を消していない。同じ穴をもう一度掘らないため。
試験は「食い違っていること」を固定する形から「解消した状態が保たれていること」を
見る形に書き換えてある。

1. **target_volume 500 mL が円筒部に入らなかった。**（解消済み）
   `h = V/(pi*R^2)` で 500 mL を入れると h = 150.68 mm で、body_height = 150 mm を超える。
   500 mL は肩まで使う量で、円筒部だけなら 398 mL しかない。
   目標を 400 mL に下げ、頭上空間 29.5 mm を確保した。
   `test_target_volume_leaves_headroom` が、この余裕が残っていることを見る。

2. **充填が停止時間に収まらなかった。**（解消済み）
   rev.3 は 停留 1.5 s に対し 開始遅れ 0.05 + 弁開 0.03 + 充填 1.212 + 弁閉 0.03 = 1.322 s。
   余裕 0.178 s。`test_fill_fits_in_the_dwell` がこれを見る。

3. **こぼれ体積の見積もりが 1〜2 桁大きい**（6 節）。未解消。
   ただし rev.3 の傾き（ピーク 68 mrad）では液面が縁に届かないので、
   この機械の既定条件ではそもそもこぼれない。突き合わせに出てくるのは、
   わざと割出しを詰めた条件だけ。

4. **`dwell_time` と `fill_height` は params.json に置かない。**
   どちらも他の値から一意に決まる（停止時間 = タクト − 割出し時間、
   液深 = 目標体積 / 円筒部の断面積）。`params.py` が読み込み時に導出している。

5. **定常状態の数え方が 1 本ずれていた。**（解消済み・11 節）
   「満量 7 本 + 空 1 本（J_load = 0.7621）」は工程配置と合わない。
   排出 225° の配置では 満量 5 本 + 空瓶 1 本 + 空ホルダ 2 つで J_load = 0.71904、
   剛体換算のピークトルク 1.38748 N·m。
   `test_the_seven_full_bottle_count_is_wrong` を番人として残してある。

6. **定常状態をホルダ番号で固定していた。**（解消済み・11 節）
   `steady_holders()` がホルダ `N-2` / `N-1` を空・空瓶と決め打ちしていたので、
   排出角が「供給角 − 1 ピッチ」のときにしか合わなかった。排出が 270° から 225° に
   動いた時点で幾何と食い違う（滞留 6 割出しに対して `N-1 = 7`）。
   いまは工程角から `n_res` と各ホルダの齢を出して作る。

7. **入力軸トルクのピークは「トルク最大 × 速度最大」ではない。**（解消済み）
   トルクの最大は psi = 22.5°、速度の最大は psi = 90° で、同時に起きない。
   積が最大になるのは psi = 51.7° で、そこでの入力軸トルクは 0.40290 N·m（慣性負荷だけ）。
   2 つの最大値を掛けると 0.718 N·m になり、1.78 倍の過大評価になる。
   ピーク機械出力も同じ理由で 0.7173 W（1.36 W ではない）。

8. **スロッシング反力トルクの符号が逆だった。**（解消済み）
   `T_table = J*al + c*om + T_slosh` としていたが、`T_slosh` は「テーブルが受ける側」の
   符号（MODEL.md 2.4）なので **引く**のが正しい。準静的極限では
   `T_slosh = -m1*Rp^2*al` になり、引くと揺動質量が慣性として素直に足される。
   足す向きだと同じ極限で揺動質量ぶんの慣性が引かれてしまい、物理として成立しない。
   テーブル軸ピークトルクで 1.3428 → 1.42007 N·m（5.8%）動く。
   液がホルダに返す力（`liquid_force`）も同じ理由で反作用側に揃えた。

9. **閉じ遅れ故障が過充填にならなかった。**（解消済み）
   閉じ命令が故障ぶんの追加遅れまで先読みしていたので、遅れが伸びても 400 mL のままだった。
   制御側は弁の劣化を知らないので、先読みするのは公称の 30 ms だけ。
   いまは 449.5 mL になる。

## 9. params.json が決めていないので、こちらで決めた取り決め

C 実装と数字を合わせないと突き合わせが成立しない。ref.py の該当箇所にも同じことを書いた。

1. **受け渡しの時刻。** 排出（225°）と供給（315°）は停留の先頭で一瞬に起きるものとした。
   星車との当たりの大きさ（速度・剛性）は params.json に無いので、イベントに時刻と
   質量だけを載せて、力は入れていない。
2. **弁の閉じ命令の出し方。** **公称の**閉じ遅れ 30 ms を先読みして早めに命じる、とした。
   こうすると正常時はちょうど 400 mL で止まり、閉じ遅れ故障（+150 ms）のときだけ
   過充填 49.5 mL（400 -> 449.5 mL）+ 液垂れ 3 mL になる。命令の出し方は params.json に無い。
   **故障ぶんの遅れは先読みしない。** 制御側は弁が劣化したことを知らないため。
3. **減衰を掛ける速度。** 回転座標系での相対速度に掛けている（壁の境界層が減衰の実体
   なので相対のほうが素直）。慣性系の微分に掛ける流儀との差は 2*zeta*Omega/w1 ≈ 4e-4 で、
   ピーク傾きの差は 7e-5 mrad。どちらでも数値は動かないが、相対に掛けると
   反力の式 `a1 = -(g*phi + 2*zeta*w1*L1*phi')` が近似なしで閉じる。
4. **排出したボトルの液。** 揺れたままテーブルから消える。イベントにそのときの体積・
   傾き・角速度を残し、連続量には段差を作らない。
5. **充填ジェットの落差。** ノズル出口から液面までの距離が params.json に無いので既定 0。
   着液速度 = ノズル流速 2.144 m/s、力 0.707 N。落差 50 mm を入れると 0.79 N（+12%）。
6. **J_load の液の数え方。** 既定は液を全量剛体として数える。スロッシングの反力トルクを
   別に足すときは m0（= 1 - 0.1225）だけを剛体で数える。両方やると二重計上になる。
   `simulate()` は後者（定常で 0.70664）。全量剛体で数えると 0.71904。差は -1.7%。
7. **反力の符号。** 力もトルクも「テーブルが受ける側」に揃える（MODEL.md 2.4）。
   `liquid_force()` が返すのは `-(m0*a_tank + m1*a1)`、空瓶の慣性反力も `-m*a`。
   ログの `f_tab_x` / `f_tab_y` はこの向きの世界座標成分で、前版とは符号が逆。
8. **在荷フラグ。** `V_i = 0` では「空瓶が載っている」と「ホルダが空」を区別できないので、
   ログに `present`（ホルダごとの真偽）を持たせた。C 側のダンプでは 0/1 の 1 バイト。

## 10. コリオリ（回転座標系で解くということ）

回転する基底 `r^`, `t^` で振り子を解くと、慣性系の式には無い 3 項が出る。

```
phi_r'' =  2*Omega*phi_t' + alpha*phi_t + Omega^2*phi_r - 2*zeta*w1*phi_r' - w1^2*phi_r - a_r/L1
phi_t'' = -2*Omega*phi_r' - alpha*phi_r + Omega^2*phi_t - 2*zeta*w1*phi_t' - w1^2*phi_t - a_t/L1
```

`2*Omega*phi'` がコリオリ、`alpha*phi` がオイラー、`Omega^2*phi` が遠心。

**分裂は解析的に出る。** `z = phi_r + i*phi_t` と置くと（減衰なし・Omega 一定）

```
z'' + 2i*Omega*z' + (w1^2 - Omega^2) z = 0   →   lambda = w1 - Omega , -(w1 + Omega)
```

固有振動数が `w1 ± Omega` の 2 本に割れる。分裂の割合はちょうど `Omega/w1`。
test_ref.py の `test_coriolis_splits_the_mode_by_omega` は、片方の円モードだけを励起して
周期を測り、この 2 本を数値で確かめている。

**この機械での大きさ。** 共振の半値半幅は `zeta*f1 = 0.0188 Hz`。分裂幅は Omega の関数で、

| Omega | 分裂 | 半値幅の何倍 |
|---|---|---|
| 0（停留） | 0 | 0 |
| 0.5236 rad/s（割出しの平均） | 0.0833 Hz | 4.4 |
| 0.9213 rad/s（ピーク） | 0.1466 Hz | 7.8 |

**「±3.3%」という 1 つの数字は、この機械では書けない。** Omega が割出しの間ずっと
変わるからで、3.3% は 0.7854 rad/s（前版の台形プロファイルのピーク角速度）に当たるが、
カム曲線ではその値を通過するだけの点でしかない。分裂は入力ではなく結果なので、
ref.py はどこにもハードコードしていない。

**効き方。** 割出し 1 回（満量・静止から）の残留揺れは

| | 割出し中のピーク | 停留の残留 |
|---|---|---|
| コリオリ入り（正） | 68.07 mrad | 35.30 mrad |
| コリオリ無し（前版） | 68.08 mrad | 38.45 mrad |

ピークは強制応答が支配的なのでほとんど動かない（差 5e-5 rad）。
残留は 8% 小さくなる。分裂で共振から外れるぶん。

## 11. 受け渡しの手順と定常状態

工程は単ノズルで、供給 315° / 充填 0° / 排出 225°。1 本のボトルの一生は

```
停留 D0: 315° で供給（空瓶）
割出し -> 0°
停留 D1: 充填（400 mL）
割出し x5 -> 225°
停留 D6: 排出
割出し x2 -> 315°（このホルダは 2 回ぶん空のまま動く）
```

滞留は割出し 6 回 = 18 秒。**割出し中にテーブルに載っているのは**

| 世界角 | 中身 |
|---|---|
| 315° | 空瓶（供給されたばかり） |
| 0〜180° | 満量 5 本 |
| 225° | ボトル無し（排出済み） |
| 270° | ボトル無し（供給待ち） |

満量 5 本 + 空瓶 1 本 + 空ホルダ 2 つ = 2.150 kg。
`J_load = 0.6102 + 2.150*0.225^2 = 0.71904 kg m^2`、
剛体換算のピークトルク `0.71904*1.92962 = 1.38748 N·m`。

**排出を供給の 1 ステーション（45°）先に置けない**のは幾何の都合で、
供給側と排出側の星車が抱えるボトルどうしが当たるため（params.json の
`stations._fix_note`）。2 ステーション = 90° が最小で、だから排出は 225°。
その結果、空のまま回るホルダが 1 つから 2 つに増える。

「満量 7 本 + 空 1 本」と数えると 3.0 kg / 0.7621 / 1.4705 になるが、これは
排出済みのホルダにもボトルが載っている勘定で、工程配置と合わない。

**ホルダ番号を固定で書かないこと。** 並びは工程角から作る。

```
n_res = ((discharge - infeed)/pitch) mod N          # 滞留の割出し回数 = 6
k_i   = ((i*pitch - infeed)/pitch) mod N            # ホルダ i の齢
k >= n_res -> ボトル無し / k == 0 -> 空瓶 / それ以外 -> 満量
```

排出角を 270° に戻せば、この式のまま 滞留 7・満量 6 本 + 空瓶 1 + 空ホルダ 1 に戻る
（`test_steady_state_follows_the_process_angles`）。

**曲げモーメントはこの偏りから出る。** 全ホルダが同じなら 8 方位の和が消えるので、
残るのは中身の差だけ。満量からの欠けは 225°/270° でボトルごと 0.425 kg、
315° で液の 0.400 kg。3 本のベクトル和は 1.0085 kg 相当で、

```
M = 1.0085 * 9.80665 * 0.225 = 2.2251 N·m
```

が常時テーブル角に同期して回っている。充填中は噴流の 0.159 N·m が乗り、
充填の進み具合でも動くので、通しで拾うと 2.2249 〜 2.3795 N·m の間を往復する。
排出が 270° だった旧配置では 1.68 N·m だった（空ホルダが 1 つ少なかったぶん）。
